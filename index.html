eBaymag（マグ）の送料をAPIで変える手順

対象: eBayの受講者と、作業を行う開発担当 / 根拠: 2026年10月2日の実機検証（ある国のサイトで実施）

表記: 確認済み は実際に読み取りや試験で確かめた内容、未確認 はまだ確かめていない内容です。MAG（マグ）は eBaymag のことです。

この記事でわかること

マグ経由で各国サイトに出ている商品の送料を、マグの画面を使わずに、eBayの公式APIだけで変える方法をまとめます。流れは「数える → ポリシーを書き換える → 出品ごとに付け直す → 確かめる」の4段階です。

ただし、この方法ではマグの画面の数字は古いままになります。メリットと限界の両方を、下の説明で確認してください。

1. 先に知っておくこと

  • 確認済み マグ自体には、公開されたAPIがありません。
  • マグの画面をブラウザ操作で自動化する方法は、この手順では使いません。eBayの公式APIだけを使います。
  • 確認済み マグが各国サイト（各国のeBayサイト）に作ったポリシーと出品は、eBayのアカウントに属しています。そのため、eBay公式APIで読み書きできます。

全体のイメージ

2. 4つの手順

1変える前に、全件を数える

どのサイトに、マグのポリシーを使う出品が何件あるかを、全件で数えます。「ポリシーがある」ことと「そのポリシーを使う出品がある」ことは別です。

  • 使うAPI: Trading API の GetSellerList（ページを最後までたどり、サイト別・ポリシー別に集計します）。
  • APIが返した総数と、集めた件数が一致することを確かめます。
  • 確認済み 検証時は、ポリシーだけがあって出品が0件のサイトがありました。最初に数えないと、意味のない検証をしてしまいます。

2サイトのポリシーの送料を書き換える

使うAPI（Account API）: 読み取りは getFulfillmentPolicies（marketplace_id をクエリで指定。例: EBAY_XX、XX にはサイトの国コードが入ります。一般的な指定例: EBAY_GB（イギリス）・EBAY_DE（ドイツ）・EBAY_FR（フランス）・EBAY_IT（イタリア）・EBAY_ES（スペイン）・EBAY_AU（オーストラリア）・EBAY_CA（カナダ）など）または getFulfillmentPolicy（ポリシーIDで指定）。更新は updateFulfillmentPolicy（ポリシーIDで指定。marketplaceId を含む全体の内容を送ります）。

  1. ポリシー全体を GET で読み取る。
  2. 読み取った内容を、控えファイルとして保存する（元に戻すための保険です）。
  3. 送料の金額だけを変えた全体の内容を、PUT で送る。
  4. もう一度 GET で読み直し、控えと比べて、変えた項目だけが違うことを確かめる。

確認済み 書き換えは成功し、読み直しで全項目が一致しました。別の機会（本体ポリシーの更新）では、更新が 20500 エラーを返したのに、読み直すと実際には反映されていた事例がありました。エラーが出たら再送せず、必ず読み直して確かめてください。

3出品ごとに、同じポリシーを付け直す

ポリシーを書き換えただけでは、出品の送料は変わりません。出品1件ずつに、同じポリシーIDをもう一度付ける更新（Revise）が必要です。

  • 使うAPI: Trading API の ReviseFixedPriceItem（SellerProfiles に同じポリシーIDを指定。サイトは、その出品があるサイトを指定します）。
  • 件数が多い場合は、Sell Feed API の一括更新（LMS_REVISE_FIXED_PRICE_ITEM）を使う方法もあります。未確認 一括更新は今回の検証では試していません。

4買い手から見える送料で確かめる

  • 使うAPI: Browse API の getItem。ヘッダー X-EBAY-C-ENDUSERCTX に contextualLocation=country=XX の形で国コードを指定します（郵便番号を足せます）。その国の買い手に見える送料が返ります。確認済み この方法は 2026-10-21 に国別の送料を見るのに使えました。10-02 の検証で使った方法ではありません。
  • 書き換え前後で、国ごとの送料を比べます。

確認済み 2026-10-02 の検証では、Trading API で出品を読み直して送料が 0.0 から 1.0 に変わったことと、商品ページの表示が「送料無料」から元の値より少し高い金額に変わったことを確かめました（Browse API ではありません）。少し高くなる理由は 未確認 です。

3. 注意すること

マグの画面は、API で変えた内容を反映しません。約6時間たっても、画面は元の数字のままでした。マグの設定と実際の出品が食い違った状態になります。

  • 確認済み マグは、最後の書き込みから約6時間のあいだ、API で変えた内容を書き戻しませんでした。
  • 未確認 マグの「Apply changes」や「Resync Shipping Profile」を押したとき、API で変えた内容がマグ側の数字で上書きされるかは、試していません。
  • 未確認 「Resync Shipping Profile」で、元の（アメリカ側）ポリシーの変更が本当に取り込まれるかも、試していません。公式ヘルプの中でも、取り込まれると書いてあるページと、再同期されないと書いてあるページがあり、食い違っています。
  • 確認済み 2026-10-21 のAPI読み取りで確認: マグが作る各国サイトのポリシーのコピーは、配送サービスの行が1本で、国ごとの行は持っていません。各国のポリシーに国別の行を足せるかは、未確認（試していません）。
  • 推定 マグがコピーするのは、配送サービスの行の送料だけで、送料表（rate table）の金額はコピーされないと考えられます。2件の比較からの推定で、反例は試していません。
  • 確認済み 別の利用者の事例で、マグに「元の配送情報がないため、再同期できません」と表示されることを確認しました。原因は、元のアメリカ側ポリシーを削除したことだと推定しています（マグは元ポリシーとIDで結びつくため）。
  • 同じ種類の配送サービスの行が重なると、マグは国ごとに安い方を残します。そのため「Worldwide $0」の行があると、ヨーロッパ向けの$7が$0に負けます。この点は、別の調査報告で 2026-10-21 に確認しています。詳しくは マグ送料ゼロ問題の調査報告 をご覧ください。

一度APIで変えたら、その後の変更もその都度APIで

APIで変えた内容はマグの画面に反映されません（確認済み 2026-10-02）。そのため、マグの画面は古い数字のままで、実際の出品とずれていきます。

  • 推定 ずれた状態のままなので、以後の送料変更も、その都度APIで行う必要があると考えられます。
  • 推定 マグの画面で送料を編集すると、古い数字を出発点にすることになります。
  • 未確認 マグの「Apply changes」や「Resync Shipping Profile」で、API の変更が元に戻るか。
  • 未確認 API で変えた後にマグが新しく作る出品が、変更後のポリシーの送料を使うか。

安全のための決まり

  1. 書き込む前に、必ず控え（バックアップ）を取る。
  2. 失敗した書き込みを、自動で再送しない。必ず読み直して、反映されたかどうかを確かめてから判断する。
  3. 最初は、ポリシー1つ・出品1件だけで試す。問題がなければ広げる。
  4. 試験で値を変えたときは、控えと比べて差が0件になるまで元に戻す。

5. まとめ

  1. マグの画面を使わなくても、各国サイトのポリシーと出品は、eBay公式APIで直接変えられます。
  2. 手順は「全件を数える → ポリシーの送料を書き換える → 出品ごとに同じポリシーIDを付け直す → 買い手から見える送料で確かめる」です。
  3. ポリシーの書き換えだけでは、出品の送料は変わりません。出品ごとの付け直しが必要です。
  4. マグの画面は古い数字のままになります。マグで「Apply changes」などを押したときの動きは未確認なので、慎重に扱ってください。
  5. 必ず控えを取り、失敗した書き込みは再送せず、まず1件で試してください。

この記事は、2026年10月2日にある国のサイトで行った実機検証と、公式ヘルプの記載にもとづいています。未確認と書いた点は、確かめられるまで事実として扱わないでください。
